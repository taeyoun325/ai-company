# AI 에이전트 컴퍼니

Claude 2명 + Gemini 1명이 채팅으로 협업해서 실제 프로그램을 만드는 로컬 웹 앱.
설계 근거와 전체 구조는 [BUILD_PLAN.md](BUILD_PLAN.md)에 있습니다.

## 실행

```bash
pip install -r requirements.txt
```

### 1) 모델 없이 UI만 보기 (API 키 불필요)

```bash
python server.py --mock
```

`http://127.0.0.1:8000` 접속. 대본화된 응답으로 QA 반려 → 재작업 → 통과 흐름 전체가
돌아가고, 프로젝트 폴더에 진짜 파일이 생기고 pytest도 실제로 실행됩니다.

### 2) 실제 모델로 실행

```powershell
$env:ANTHROPIC_API_KEY = "sk-ant-..."
$env:GEMINI_API_KEY    = "..."
python server.py
```

## 화면 (홀로그래픽 UI)

```
┌──────────────┬─────────────────────────────┬──────────────┐
│ AGENTS       │  AI AGENT COMPANY    [LIVE] │ 태스크 보드  │
│  ◈ PM        │  ◈ PM · CLAUDE              │  [✔] t1      │
│   IN/OUT/$   │  └ 작업을 쪼갰습니다         │  [▶] t2      │
│  ◆ DEVELOPER │  ◇ QA · GEMINI              ├──────────────┤
│   IN/OUT/$   │  └ 테스트를 먼저 작성합니다  │ 산출물       │
│  ◇ VERIFIER  │  ◆ DEV · CLAUDE             │ ▸ src/calc.py│
│   IN/OUT/$   │  └ src/calc.py 새로 만듦     │ ▸ tests/…    │
├──────────────┤  ⬡ SYSTEM                   │  (클릭→코드) │
│  완성도      │  └ 격리 실행 · 3통과·0실패   ├──────────────┤
│   ◕ 100      │  ◇ QA · GEMINI              │ 저장소       │
│  태스크 2/2  │  └ 통과 — 인수기준 충족      │  프로젝트별  │
│  기준커버3/3 ├─────────────────────────────┤  완성도 점수 │
│  재작업 1회  │  [요구사항]          [착수]  │              │
└──────────────┴─────────────────────────────┴──────────────┘
```

- **에이전트 카드** — 실행 중인 에이전트에 발광 테두리와 맥박이 돕니다.
  각 카드에 입력/출력 토큰과 누적 비용, 상대 소비량 막대가 실시간으로 찍힙니다.
- **말풍선** — 실선은 팀에게 하는 말, 점선은 툴 호출(파일 읽기/쓰기, pytest).
- **저장소 카드** — 클릭하면 그 프로젝트의 파일 목록으로 바뀌고, 파일을 클릭하면
  코드 뷰어가 열립니다.

## 신뢰 경계 — 이 프로그램의 핵심 설계

**구현자는 검증기를 고칠 수 없다.** 이것 하나가 나머지를 지탱합니다.

```
프로젝트/
  src/     ← DEV만 쓰기 가능. QA는 읽기만.
  tests/   ← QA만 쓰기 가능. DEV는 읽지도 못함.
  pytest.ini ← 오케스트레이터 소유. 매 실행마다 덮어씀.
```

순서도 바뀝니다. **테스트가 구현보다 먼저** 나옵니다.

```
PLAN(PM) → WRITE_TESTS(QA) → IMPLEMENT(DEV) → TEST → REVIEW(QA)
```

DEV가 테스트를 쓰면 통과시키려고 테스트를 고칩니다(`assert True`).
그래서 검증자가 인수기준만 보고 테스트를 먼저 쓰고, 구현자는 그 파일을
읽지도 고치지도 못합니다. DEV에게는 대신 **인수기준을 보여줍니다** — 그게 계약서입니다.

`conftest.py`, `pytest.ini`, `pyproject.toml`, `setup.cfg`, `sitecustomize.py`,
`usercustomize.py`, `*.pth` 는 **어느 역할도 만들 수 없습니다.** 전부 pytest나
파이썬이 자동으로 읽어들여 테스트 실행 환경 자체를 바꿀 수 있는 파일입니다.

## 완성도 계산

| 시점 | 계산식 |
|---|---|
| 진행 중 | `70% × 태스크 완료율 + 30% × 테스트 통과` |
| 최종 검수 후 | `충족된 인수기준 id / 전체 인수기준 id` |

**검수 통과율은 일부러 뺐습니다.** QA가 관대할수록 점수가 오르는 순환논리가 되기
때문입니다. 남은 두 항목은 QA 판단과 독립적입니다 — 태스크 완료는 오케스트레이터가
세고, 테스트 통과는 파이썬이 실행한 결과입니다. 검수 통과율은 참고 지표로
계기판에만 남겨뒀습니다.

`기준 커버`는 **테스트가 붙은 인수기준 비율**입니다. 3/5라면 두 기준은 아무도
자동 검증하지 않고 있다는 뜻이니, 완성도 100이어도 그대로 믿으면 안 됩니다.

가중치는 `orchestrator.py`의 `W_TASK, W_TEST`에서 조정합니다.

## 저장소

제작한 프로그램은 실행할 때마다 **프로젝트별 폴더**로 나뉘어 쌓입니다.

```
projects/
  20260905-1432-사칙연산-계산기-모듈과/
    .meta.json          ← 요구사항 · 완성도 · 태스크 · 에이전트별 토큰 · 비용
    pytest.ini          ← 오케스트레이터 소유
    src/calc.py         ← DEV가 씀
    tests/test_calc.py  ← QA가 먼저 씀
  20260905-1510-TODO-REST-API/
    .meta.json
    src/app.py
    tests/test_app.py
```

`.meta.json`은 라운드마다 갱신되므로 중간에 죽어도 그때까지의 기록이 남습니다.
에이전트의 파일 툴은 **현재 프로젝트 폴더 밖으로 나갈 수 없고**, `.meta.json`도
수정하지 못합니다(`tools/fs.py`).

REST API:

| 엔드포인트 | 용도 |
|---|---|
| `GET /api/projects` | 프로젝트 목록 (완성도·비용·파일 수 포함) |
| `GET /api/projects/{slug}` | 프로젝트 상세 + 파일 목록 |
| `GET /api/projects/{slug}/file?path=` | 파일 내용 |
| `GET /api/stream` | SSE 실시간 이벤트 |

## 구성

| 파일 | 역할 |
|---|---|
| `orchestrator.py` | 상태머신 + 완성도 산출. **누가 다음에 말할지는 LLM이 아니라 여기가 정한다** |
| `usage.py` | 에이전트별 토큰·비용 집계 (Claude·Gemini 양쪽을 한 곳으로) |
| `store.py` | 저장소 — 프로젝트 폴더와 `.meta.json` |
| `bus.py` | 이벤트 버스. 백그라운드 스레드 → SSE 브리지, `logs/trace.jsonl` 기록 |
| `server.py` | FastAPI |
| `web/index.html` | 홀로그래픽 UI (외부 의존성 0, 단일 파일) |
| `agents/pm.py` | 계획. 파일 쓰기 권한 없음 |
| `agents/dev.py` | 구현. Tool Runner. src/에만 쓰기, tests/ 접근 불가 |
| `agents/qa.py` | 테스트 작성 + 판정. Gemini. src/는 읽기만 |
| `runner.py` | 생성 코드를 실행하는 유일한 지점. 격리·세탁·트리 종료 |
| `agents/mock.py` | 대본 에이전트 (`--mock`). 가짜 토큰 사용량까지 흉내 냄 |
| `prompts/*.md` | 시스템 프롬프트. **품질의 8할이 여기 있음** |
| `tools/fs.py` | **역할별 쓰기 권한.** DEV=src/, QA=tests/. 금지 파일명 차단 |

## 안전장치

`config.py`에서 조정합니다.

- `MAX_ROUNDS` (40) — 전체 턴 상한
- `MAX_REWORK` (3) — 태스크당 반려 허용 횟수. 넘으면 PM이 태스크를 다시 쪼갬
- `MAX_REPLANS` (3) — 전체 재기획 허용 횟수. 없으면 재기획 루프가 돌 수 있음
- `BUDGET_USD` (5.0) — 누적 비용 상한. **호출 전에** 최악 비용을 더해서 검사합니다.
  사후 감지는 상한이 아니라 부고입니다 — DEV 한 번이 예산을 통째로 넘길 수 있으니까요.
- 경로 탈출 차단 — `Path.resolve()`로 심링크까지 해석한 뒤 루트를 비교합니다.

### 생성된 코드 실행 (`runner.py`)

가장 위험한 지점입니다. 막는 것과 **막지 못하는 것**을 정직하게 적습니다.

막는 것:

| 위협 | 방어 |
|---|---|
| API 키 유출 | 환경변수 세탁 — `KEY`/`TOKEN`/`SECRET`/`ANTHROPIC`/`GEMINI` 등이 이름에 든 변수 제거 |
| `usercustomize.py` 자동 실행 | `PYTHONNOUSERSITE=1`, `-I`(격리 모드) |
| 프로젝트 설정 파일로 우회 | 고정 `pytest.ini`를 `-c`로 강제, `-p no:cacheprovider` |
| 좀비 프로세스 | 프로세스 그룹 생성 후 `taskkill /T`(Windows) / `killpg`(POSIX)로 트리 전체 종료 |
| 무한 루프 | `TEST_TIMEOUT` (기본 120초) |

**막지 못하는 것:**

- **네트워크 송신.** 생성된 코드가 로컬 파일을 읽어 외부로 보내는 것은 막을 수
  없습니다. OS 수준 격리(컨테이너, 방화벽 규칙)가 필요합니다.
- **홈 디렉터리 읽기.** 자식 프로세스는 당신의 사용자 권한을 그대로 갖습니다.

키를 지워도 이 두 가지는 남습니다. 신뢰할 수 없는 요구사항을 돌릴 거라면
**이 앱 자체를 컨테이너 안에서 실행하세요.** 개인이 자기 아이디어를 구현시키는
용도라면 위 방어로 충분히 합리적이지만, "안전하다"고 말하지는 않겠습니다.

## 알아둘 것

- **Gemini 모델 ID**는 시점에 따라 바뀝니다. 첫 실행 전 `client.models.list()`로
  최신 pro 계열 ID를 확인하고 `config.QA_MODEL`에 박아두세요.
- `config.PRICES`의 Gemini 단가는 근사치입니다. 정확한 비용이 필요하면 실제 단가로 고치세요.
- QA 프롬프트의 *"지적할 것이 없으면 억지로 만들지 말고 pass를 내라"* 문장을
  지우지 마세요. 이게 빠지면 검증자가 영원히 트집을 잡아 루프가 끝나지 않습니다.
- 모든 턴이 `logs/trace.jsonl`에 남습니다.
- **캐시 적중을 계기판에서 확인하세요.** `캐시 읽기`가 계속 0이고 빨갛게 뜨면
  프롬프트 캐싱이 걸리지 않는 것입니다. `cache_control`을 붙였다는 사실과 캐시가
  적중했다는 사실은 다릅니다 — 프리픽스가 모델의 최소 캐시 길이(512~4096 토큰)
  미만이면 조용히 무시됩니다. 그 상태에서는 "캐싱으로 비용을 아꼈다"고 말할 수 없습니다.
- **`기준 커버`가 전체보다 작으면 완성도 숫자를 의심하세요.** 테스트가 없는
  인수기준은 아무도 자동으로 검증하지 않습니다. QA가 `uncovered`로 표시한 항목은
  사람이 직접 봐야 합니다.
- QA가 쓴 테스트가 틀릴 수도 있습니다. 너무 엄격하면 정상 구현이 계속 반려되고,
  너무 느슨하면 틀린 구현이 통과합니다. `MAX_REPLANS`에 걸려 중단되면 대개
  전자이니, `tests/`를 직접 열어보세요.
